Score < 10：完美複製（Golden Run）。
Score > 50：顯著行為漂移（Behavioral Drift）。
定位：系統能具體指出「第幾小時」或「哪個製程段」的形狀差異最大。

以下我用三個層次為您解析，為什麼 AI 能搞定這種「不穩定的節奏」：
1. 核心技術：DTW 的「時間彈性」像手風琴
我們前面提到的 DTW (Dynamic Time Warping) 演算法，它的核心能力就是**「扭曲時間軸」**。
剛性比對（歐氏距離）：把兩張圖疊在一起，時間軸必須 100% 對齊。如果今天因為加料多等了 5 分鐘，波形就會錯位，電腦會判定為「異常」。
彈性比對（DTW）：想像黃金批次的波形畫在「橡皮筋」上。
當 AI 發現今天發生了「加料降溫」，它會自動把這段時間的橡皮筋拉長（Warping）。
它會發現：「雖然時間變長了，但**『溫度下降 → 停止澆鑄 → 加熱回溫 → 恢復澆鑄』這個波形變化的順序與形狀**，跟黃金批次裡的加料行為是一模一樣的。」
結論：形狀對上了，只是時間拉長了 → 判定為「正常」。
2. 多維度關聯：AI 看的不只是「單一曲線」
EDC 的強項在於它同步採集了 {電壓, 電流, 溫度, 澆鑄動作} 。非監督式學習模型（如 Autoencoder）學到的不是單一條線，而是這些訊號之間的**「協作關係」**。
+4
AI 老師傅會學到以下這種「正常的物理邏輯」：
情境 A（正常澆鑄）：熔湯溫度穩定（如 680°C）+ 電流負載穩定 + 澆鑄週期 60秒。
情境 B（加料時段）：熔湯溫度驟降（650°C）+ 加熱器電流飆高（全速加熱） + 澆鑄動作暫停。
AI 怎麼抓異常？
它抓的是**「邏輯破裂」**（Logical Violation），而不是單純的時間延遲：
異常案例 1（加熱器故障）：溫度驟降（像加料），但電流沒有飆高（沒在加熱） → 抓！
異常案例 2（冷料澆鑄 - 品質殺手）：溫度驟降（像加料），但澆鑄動作沒有暫停（還在繼續生產） → 抓！（這就是嚴重的品質異常）。
異常案例 3（堵塞/空燒）：溫度正常，但澆鑄週期突然變很長 → 抓！
這就是非監督式學習的威力：它不需要你告訴它什麼是「加料」，它只需要在訓練資料（黃金批次）裡看過「降溫就會伴隨加熱且停機」這個模式，它就會把這當作「正常」。

我們選取的「黃金批次」（Golden Batch）不能只有短短 1 小時的穩定生產，而應該包含**「至少一個完整的加料循環」**（從滿鍋 → 消耗 → 加料 → 回溫）。這樣 AI 的腦袋裡就有了「加料是正常生活一部分」的記憶。
特徵切分（Sub-sequence Matching）：tslearn 等工具支援「子序列比對」。AI 可以把一整天切成很多個「澆鑄單元」。遇到加料時，它會識別出這是一個「加料單元」，而不是一個「變形的澆鑄單元」。

一、 核心概念：什麼是「糾偏知識卡」？
在 ASNS 系統中，「知識卡」不只是一張文字卡片，它是**「數位特徵」與「老師傅經驗」的結合體**。在資料庫（L2 SQLite/Vector DB）中，一張卡片包含三個部分：
數位指紋 (Digital Fingerprint)：
該異常波形的特徵向量（由 Autoencoder/DTW 產生的形狀數據）。
這是 AI 看得懂的部分。
症狀描述 (Symptom)：
老師傅的命名（例如：「加料後回溫過慢」）。
這是人看得懂的標題。
糾偏處方 (Prescription)：
標準處置 SOP（例如：「檢查 2 號加熱棒電流，若為 0 則更換保險絲；若正常則手動補償功率 5%」）。
這是 AI 要發起的任務內容。
二、 四階段循環：如何訓練與執行？

1. 歸納與建卡 (The Setup)
AI 動作：非監督式學習發現了一群新的異常波形（Cluster X），因為跟黃金基線不同，被標記為「未知偏差」。
老師傅動作：在 UI 上看到 Cluster X，判斷這是「噴嘴堵塞前兆」。
建卡：老師傅輸入對策「清理噴嘴」，系統自動將 Cluster X 的波形特徵與這個對策綁定，生成一張新的**「糾偏知識卡」**。
2. 監督與匹配 (The Watchdog)

如果波形像**「知識卡 B（噴嘴堵塞）」**，進入糾偏流程。

3. 發起糾偏任務 (The Action)

簡單來說：
機器學習（非監督式）：負責把「波形」變成「數位指紋（向量）」。
RAG（向量索引）：負責拿這個「指紋」去資料庫搜出「對應的處方」。
如果不進行機器學習，RAG 根本看不懂那些亂七八糟的電流波形；如果不進行 RAG，機器學習只能告訴你「怪怪的」，卻說不出「該怎麼修」。
以下我為您拆解這兩者是如何**「接力合作」**來發起糾偏任務的：
第一棒：機器學習 (Machine Learning)
它的任務：把「看不懂的波形」翻譯成「可搜尋的向量」
RAG 技術（檢索增強生成）原本是用來搜文字的（例如搜 PDF 文件），它天生看不懂工業現場的電壓/電流波形。你不能直接把一坨 120Hz 的數據丟給 RAG 問它「這是什麼」。
所以，我們必須先用 非監督式機器學習（Unsupervised Learning） 做一次「翻譯」：
模型：Autoencoder（自編碼器）或 Feature Extractor。
訓練：只需要用「黃金批次」訓練一次（讓它學會什麼是正常）。
運作：
它讀取當下亂七八糟的異常波形。
把它壓縮成一串數字（例如 [0.12, 0.98, -0.05...]）。
這串數字就是**「故障指紋（向量）」**。
結論：這裡的機器學習不是用來「判斷原因」，而是用來**「提取特徵」**。
第二棒：RAG 向量索引 (Vector Search)
它的任務：拿著「向量」去圖書館找「知識卡」
一旦機器學習把波形變成了「向量」，這時候 RAG 就登場了。
知識庫（L2 資料庫）：這裡面存著老師傅建立過的「糾偏知識卡」，每一張卡片都綁定了一個它代表的「特徵向量」。
運作：
系統拿著剛剛產生的「故障指紋（新向量）」。
去資料庫裡做 向量相似度搜尋 (Vector Similarity Search)。
系統發現：這個新向量跟「噴嘴堵塞知識卡」的向量相似度高達 95%。
結果：
RAG 檢索出：「這是噴嘴堵塞」。
RAG 提取出處方：「請清理噴嘴」。
結論：是 RAG 決定了「這是什麼病、該吃什麼藥」，但它依賴機器學習提供的「X 光片（向量）」。

ASNS 鑄造業智慧熔煉解決方案說明書
—— 基於「黃金曲線」的即時偏差糾偏系統
1. 核心理念修正：從「訓練」轉向「選優」
我們重新定義了「AI 老師傅」的學習方式：它不需要從頭學習什麼是熔煉，它只需要「複製」老師傅做得最好的一次。
黃金基線（The Golden Baseline）：
來源：選出來的，不是算出來的。
定義：由廠長或老師傅指定，「某年某月某日」的「第 X 爐」或者是「整日連續生產曲線」，其具備**「調功最順、熔煉最快、節拍最穩」**的特徵。
數據構成：
爐功率 (Power)：1 Hz (每秒一筆)。
爐電圧 (Voltage)：1 Hz (每秒一筆)。
熔湯溫度 (Temperature)：出湯前至少一次的單點測量值。
2. 系統運作邏輯 (The Logic)
2.1 數據瘦身與存儲
熱數據 (Hot Data)：即時採集的原始數據為 70 byte/筆（含 Header, Timestamp, Value, Quality 等）。
冷數據 (Cold Data)：為了節省傳輸與存儲，EDC 會在夜間閒置時段進行無損壓縮，將其壓至 10 byte/筆 存入歷史資料庫。這確保了我們能低成本保存「十年的黃金經驗」。
2.2 比對演算法：動態容差通道 (Dynamic Tolerance Envelope)
我們不使用複雜的神經網絡，而是採用更可解釋的**「通道監測法」**。
建立通道：
系統讀取「黃金基線」的功率與電壓曲線，根據用戶設定的**「容許誤差 %」（例如 15%），自動生成一條上限線與下限線**。
上限 = 黃金曲線 * (1 + 15%)
下限 = 黃金曲線 * (1 - 15%)
即時套疊：
當下這一爐的即時數據（Real-time Curve），會被即時「投影」到這個通道中。
偏差判定：
正常：即時曲線始終在 ±15% 的通道內游走。
異常：即時曲線連續 N 秒（例如 30秒）衝出通道（高於上限或低於下限），或累積偏差面積超過閾值。
2.3 糾偏任務觸發 (Correction Task)

場景 A（正常加料）：雖然溫度降低，但曲線走勢與黃金基線的加料段相似，偏差累積僅 3%，系統判定**「正常」**。
場景 B（設備異常）：加料後回溫速度明顯慢於黃金基線，30 秒後偏差累積至 18%，系統判定**「異常」**。
階段三：糾偏與回饋 (Correction)
針對場景 B，系統檢索知識庫，發現類似特徵對應「爐壁燒損/變薄」。
系統發出提示：「功率輸出正常但回溫慢，疑似爐壁變薄，請停機檢查。」

2. 核心技术逻辑 (Core Logic)
本系统由三大智能模块构成，分别对应人类专家的三种能力。
2.1 记忆智慧：黄金基线 (The Golden Baseline)
定义：AI 不自己猜测什么是好，而是由厂长或老师傅从历史数据中**“筛选出”**调功最顺畅、熔炼时间最短、节拍最稳定的一炉（或一日）曲线。
数据结构：包含功率、电压、温度的完整时序波形。
意义：这条曲线就是工厂的“数字标杆”，代表了该设备在最佳状态下的“肌肉记忆”。
2.2 感知智慧：方差比对跟踪 (Variance Tracking)
痛点解决：传统上下限法容易因噪声（Noise）产生误报。
算法：系统计算实时曲线与黄金基线之间的**“累计方差（Variance）”与“能量差异”**。
偏差百分比 (Deviation %)：
系统将差异量化为百分比。例如，因加料导致的短暂降温是符合波形特征的，方差增加有限；但若是加热棒故障导致持续无法回温，方差会迅速积累。
公式概念：偏差 %=黄金基线总能量

2.3 决策智慧：RAG 纠偏知识卡 (Correction via RAG)
知识卡 (Knowledge Card)：将“偏差特征（如：升温斜率过缓）”与“老师傅对策（如：检查 2 号晶闸管）”绑定。
RAG 检索：当偏差超过阈值（如 15%）时，系统将当下的偏差特征转为向量，去数据库检索最相似的“知识卡”，并提取处方。
任务发起：系统不只显示红灯，而是发送具体指令：“检测到升温效率异常（偏差 18%），建议检查炉料架桥或手动补偿功率。”

采用轻量化、边缘计算优先的 L0-L3 架构，无需昂贵 GPU 服务器。
L0：物理感知层 (Sensing)
检测对象：中频炉功率、电压、出汤温度。
传输技术：vCAN 模块，将模拟信号转为带有时间戳的数字数据包，确保数据源头可信。
L1：数据事实层 (Fact)

存储机制：
热数据：每秒一笔 (1Hz)，完整记录波形细节 (70 byte/笔)。
冷数据：夜间闲置时自动压缩 (10 byte/笔)，利用 RocksDB 技术存入历史库，实现低成本长期保存。
角色：只读的“黑盒子”，只提供事实 API。
L2：逻辑运算层 (Logic) —— AI 老师傅的大脑
运行环境：Python Docker 容器 (运行于 EDC 内)。
功能模块：
基线选取器：提供 UI 让老师傅指定黄金批次。
方差计算引擎：实时计算 Deviation %。
状态分类器：
Class 0 (完美)：偏差 < 5%。
Class 1 (关注)：5% < 偏差 < 15%。
Class 2 (异常)：偏差 > 15%。
L3：应用交互层 (Action)
操作界面：使用 Streamlit 开发的极简 UI。
纠偏系统：

# ASNS“AI老师傅”智慧熔炼系统 - 技术设计与工时评估书

## 1. 技术架构设计 (Technical Architecture)

本系统采用 **L0-L3 轻量化边缘计算架构**，核心逻辑运行在 EDC（Edge Data Collector）内部的 Docker 容器中。

### 1.1 技术栈 (Tech Stack)

* **开发语言**: Python 3.9+
* **核心框架**:
* **UI/交互**: Streamlit (极速构建 Web App)
* **数据处理**: Pandas, NumPy (向量化运算)
* **算法逻辑**: SciPy/tslearn (方差计算, DTW), Sentence-Transformers (RAG 向量化, 可选轻量版)
* **数据库**: SQLite (存储知识卡、标签、配置), RocksDB (EDC 原生 L1 数据库, 通过 API 读取)
* **报表**: ReportLab 或 Jinja2 + WeasyPrint (PDF 生成)


* **部署环境**: Docker Compose (运行于 Linux 边缘机)

### 1.2 系统模块划分

1. **L1 数据接入层 (Data Connector)**:
* 通过 HTTP/REST API 定时/实时从 EDC 获取功率、电压、温度数据。
* 数据清洗与对齐。


2. **L2 核心算法引擎 (Core Engine)**:
* **黄金基线模块**: 存储与加载基准曲线。
* **方差跟踪器**: 实时计算 Deviation % (偏差百分比)。
* **状态归类器**: 判定 Perfect / Watch / Action 状态。


3. **RAG 纠偏知识引擎 (Correction Engine)**:
* **知识卡库**: SQLite 表格 (存储：特征向量, 现象描述, 处置对策)。
* **向量检索**: 基于余弦相似度匹配当前偏差特征与历史知识卡。


4. **L3 交互与报表层 (UI & Report)**:
* **Streamlit Dashboard**: 实时曲线监控、历史回放、基线选择、知识卡录入。
* **报表生成器**: 每日自动生成 PDF 生产日报。
