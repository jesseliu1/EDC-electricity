### P0 从宿主进入 EDC 后 Dashboard 首屏统计与最近炉次请求超时，页面进入“假空态”
- **状态**: 新发现待处理（2026-03-21）
- **页面/模块**: ASNS 宿主入口 -> EDC / Dashboard
- **复现步骤**:
  1. 启动宿主、后端与 EDC 前端
  2. 从宿主桌面双击 `EDC electricity` 进入内嵌 EDC
  3. 观察 Dashboard 首屏统计卡与“最近炉次”区域
  4. 同时查看浏览器控制台与后端接口耗时
- **实际结果**:
  - 宿主入口已成功打开 EDC iframe，统一运行态顶部显示“宿主已连入 · 真实链路就绪”
  - 但 Dashboard 控制台会报：
    - `Dashboard stats request failed. AxiosError: timeout of 10000ms exceeded`
    - `Dashboard recent heats request failed. AxiosError: timeout of 10000ms exceeded`
  - 页面首屏表现为：
    - 统计卡回退成 `0 / 0 / 0`
    - “最近炉次”显示“暂无炉次数据”
  - 这会让用户误判为“当前没有真实数据”，但实际上是接口超时
- **当前证据**:
  - `GET /api/dashboard/stats` 冷态实测约 `15.6s`
  - `GET /api/dashboard/recent-heats?limit=8` 冷态实测约 `3.3s`，但与 Dashboard 其它请求并发时前端仍可触发 10 秒超时
  - 浏览器 network 已记录这两条请求在前端侧被中止
  - 当前 Dashboard store 的 Axios 超时仍是 `10000ms`
- **根因初判**:
  - Dashboard 的 `stats` 与 `recent-heats` 都会走 `dashboard.py -> _sorted_dashboard_heats() -> heats.py -> _list_heat_store()`
  - 冷启动下该链路会触发真实炉次推断，导致宿主入口首次打开 Dashboard 时首屏过慢
- **期望结果**:
  - 从宿主进入 EDC 后，Dashboard 首屏应在前端超时阈值内完成加载
  - 若真实链路变慢，应明确区分“超时 / 性能问题”和“空数据”
  - 不应出现“统一运行态 ready，但 Dashboard 主卡片像没数据”的假空态
- **严重程度**: 高
- **如何测试**:
  1. 重启后端，确保 live heat 推断缓存处于冷态
  2. 从宿主入口重新打开 EDC，记录 Dashboard 首屏耗时
  3. 确认统计卡与最近炉次在 10 秒内完成真实加载，且不再报 timeout
  4. 再次刷新验证热态表现，确认冷/热态都不会误导成空态

### P1 新建基线在炉次详情 compare 中沿用来源炉次绝对时间，图表与当前炉次信息不匹配
- **状态**: 已修复待复验（2026-03-23）
- **页面/模块**: 炉次详情 / 与基线对比
- **复现步骤**:
  1. 基于某条真实炉次创建并发布新的黄金基线
  2. 打开另一条真实炉次详情
  3. 切换到刚创建的新基线 tab
  4. 观察图表横轴范围、基线曲线位置与当前炉次摘要
- **实际结果**:
  - 新建基线会直接沿用其来源炉次的绝对时间戳上图
  - 当来源炉次与当前炉次不在同一天时，compare 图表横轴会被拉成跨天范围
  - 页面视觉上只剩左右两端细线，图表与当前炉次开始/结束信息明显不匹配
- **当前证据**:
  - 复现样例中，当前炉次是 `2026-03-23 19:56 ~ 20:26`，新建基线 `范德萨` 来源炉次是 `2026-03-19 08:52 ~ 09:22`
  - 修复前 `GET /api/heats/{id}/compare` 中该基线 `metric_curves[*].baseline_curve` 仍返回 `177388...` 时间戳，而当前曲线返回 `177426...`
  - 两组曲线直接共用时间轴后，ECharts 会把图拉成跨天范围
- **根因结论**:
  - compare 展示层直接使用了“基线来源炉次的绝对时间戳”，没有把基线曲线重映射到当前炉次时间窗
  - 同时 compare 当前曲线展示窗口只看炉次本体，没有按“当前炉次前后各 60 分钟”的联调口径扩展上下文
- **修复结果**:
  - `apps/server/src/api/heats.py` 已把 compare 基线曲线重映射到当前炉次核心时间窗
  - compare 当前曲线展示已扩到当前炉次前后各 `60` 分钟
  - `apps/web/src/views/HeatDetailView.vue` 已把 x 轴固定为当前炉次前后各 `60` 分钟，避免再被历史基线绝对时间拉成跨天图
- **期望结果**:
  - 新建基线切到炉次详情 compare 时，图表应以当前炉次为锚点
  - 展示范围应为“当前炉次本体 + 前后各 60 分钟上下文”
  - 不应再出现历史来源炉次把当前 compare 图拉成跨天范围的情况
- **严重程度**: 中
- **如何测试**:
  1. 基于旧炉次创建并发布一条新基线
  2. 打开另一条日期不同的真实炉次详情并切到该基线
  3. 确认图表横轴收口到当前炉次前后各 60 分钟
  4. 确认基线曲线落在当前炉次核心窗口内，当前曲线能看到前后 60 分钟上下文
