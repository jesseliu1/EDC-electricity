- **严重程度**: 高
- **如何测试**:
  1. 完成一次基线创建并点击“发布”
  2. 确认弹窗关闭，或按钮进入不可重复点击状态

### P0 炉次浏览列表数据来源不明确，后端未连接时仅显示 2 条且无法判断是否真实数据
- **状态**: 部分收口（2026-03-20）
- **页面/模块**: 炉次浏览 / 列表页
- **复现步骤**:
  1. 进入“炉次浏览”页面
  2. 观察页面顶部提示“后端服务未连接，当前页面不会回退为 Mock 数据”
  3. 查看下方炉次列表，仅显示 2 条异常炉次
  4. 尝试判断这些炉次记录的来源
- **实际结果**:
  - 页面提示后端未连接，且不会回退为 Mock 数据
  - 但列表中仍然展示了 2 条炉次记录
  - 当前无法从页面明确判断这 2 条数据是历史缓存、真实数据、残留状态还是其他来源
  - 也无法解释为什么只剩 2 条
- **补充现象**:
  - 再次刷新后，列表又出现了大量炉次信息（示例中变为 `Total 60`，当前页显示 10 条）
  - 同一页面在相近时间内从“仅 2 条”变成“很多条”，数量表现不稳定
  - 这进一步放大了“数据到底来自哪里”的不确定性
- **当前处理结果**:
  - Heat store 已持久化筛选条件与分页，刷新后不会再因为状态重置导致“2 条 / 60 条”来回跳
  - 运行态刷新丢失问题已收口，列表稳定性比之前高
  - 炉次浏览页面现已增加来源提示，并在列表项回显“演示炉次台账”等来源标签
  - 阶段性测试已确认：当前 EDC 基座未暴露炉次台账 request，现阶段无法直接把炉次主记录替换成真实热次列表
  - 现已落第一版“真实功率曲线推断炉次”，列表会优先展示 `live_inferred` 记录，并在来源标签中明确标记“真实 EDC 推断炉次”
  - 实测当前真实 EDC 通道可推断出 63 条炉次，列表已不再只能依赖 demo seed
  - 剩余未收口点是：`live_inferred` 仍属本地启发式切割，不是上游官方炉次台账
- **期望结果**:
  - 炉次列表应明确标识当前数据来源，例如真实数据 / 本地缓存 / 演示数据 / 空态
  - 当后端未连接且未启用 mock 时，应给出一致且可解释的结果，不应出现“提示无数据回退”但列表仍有残留数据的歧义
  - 如确实来自真实链路或缓存，应在页面或调试信息中可追溯来源
  - 列表数量应符合当前数据源的实际结果，不能只留下无法解释的少量记录
- **严重程度**: 高
- **如何测试**:
  1. 在后端在线、离线、mock 关闭三种场景分别进入“炉次浏览”
  2. 对比页面提示、列表数量和接口返回是否一致
  3. 确认页面可明确说明当前数据来源
  4. 连续刷新页面，确认列表数量不会在“2 条 / 60 条”等状态间无解释跳变
  5. 确认不会出现“后端未连接但仍显示来源不明的少量炉次”这种状态
