# 代码审查技能

## 目标
对指定文件或 diff 做结构化审查，给出可落地的修改建议。

## 使用场景
- 用户说"帮我 review 这段代码"、"检查一下有没有 bug"
- 用户提交了大量变更需要审查
- 用户要求优化代码质量

## 审查步骤

1. **复述变更目标**：先说明你理解的变更意图（不确定点标"未指定"）
2. **四维检查**：
   - **Correctness（正确性）**：逻辑错误、边界条件、空值处理、类型安全
   - **Security（安全性）**：secrets 泄露、注入风险、权限边界、不安全依赖
   - **Maintainability（可维护性）**：结构清晰度、命名规范、代码重复、注释完整性
   - **Performance（性能）**：明显低效点、不必要的计算/渲染、N+1 查询

3. **输出格式**：
   ```
   ### [High/Medium/Low] 问题标题
   - **位置**：文件名:行号 或 函数名
   - **问题**：具体描述
   - **建议**：修复方案（附代码示例）
   ```

## 约束
- 不得泄露任何可能的密钥（用 `<<REDACTED>>` 替代）
- 审查意见必须可操作（有具体的修复建议，不是空泛评价）
- 对于本项目，额外检查：
  - Vue 组件是否使用了 `<script setup>` + Composition API
  - 是否有内联样式（应使用 Tailwind / Element Plus）
  - Python 代码是否使用了 async/await
  - 是否有未经 Pydantic 验证的请求数据
